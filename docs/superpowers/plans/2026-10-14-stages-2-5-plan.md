# Stages 2 to 5 implementation plan

> **For agentic workers:** execute with superpowers:subagent-driven-development, one task per subagent, a fresh reviewer per task. Tasks are sized so one subagent finishes one in a single context. Steps use `- [ ]` for tracking.

**Goal:** Build stage 2 (account contract, email, auto-lock), apply the design to the existing screens, and build the handoff subsystem in three slices, on branch `feat/stages-2-5` from `main` after the design PR merges.

**Specs:** `docs/superpowers/specs/2026-10-14-stage-2-account-contract.md`, `…-stage-2b-apply-design.md`, `…-stages-3-5-handoff.md`, under the product core spec `…-product-core-design.md` and `docs/design/decisions.md`.

**Tech:** TypeScript, Express 4, Prisma 5, Postgres, Jest, React 18, Vite, Vitest, Tailwind 3, nodemailer, Playwright (new), Web Crypto.

## Global constraints

- Every task ends green on `make typecheck` and the suite it touches; the branch ends green on all four CI jobs.
- The server never receives a password, a wrapping key, a master key, a private key, a release key, a share in clear, or a file key. A reviewer who sees one of those in a request body rejects the task.
- No email names an item. Strings for irreversible acts are the verbatim lines in `docs/design/brief/03-screens-and-flows.md`.
- `client/src/services/api.service.ts` is the contract; change it first, then the server to match.
- Each slice's migration is one committed Prisma migration.

## Review focus

1. A raw key left in `localStorage` or `sessionStorage` after lock (stage 2, task 6): the lock test must assert storage holds only wrapped blobs.
2. The register endpoint issuing tokens before verification (task 3): test asserts no `tokens` in the 201 body.
3. Shamir with a share index of 0 or a duplicated index (task 12): tests reject both.
4. Rule creation accepted with items missing for a file in the folder (task 15): test creates a folder with two files and posts one item.
5. Quorum reaching threshold with a vote from a witness who was removed after the request opened (task 20): test removes a witness mid-request and asserts the vote is rejected.

## Order and parallelism

Tasks 1 to 7 are stage 2 and go in order. Tasks 8 to 11 (design application) can run in parallel with each other after task 1 and before task 7. Tasks 12 to 21 are the handoff slices in order; 12 can run any time after task 1.
